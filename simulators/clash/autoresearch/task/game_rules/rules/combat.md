# Targeting, movement, damage and effects

## Acquisition and retention

Troops and towers select targets automatically; the policy only plays cards or waits. A target must be an opposing valid object with a health component, compatible ground/air/building flags and targetable state. Giant selects only buildings. Knight/MiniPekka cannot select air. Archer/Musketeer/towers can select either ground or air, though no air troop is generated by this deck. Enemy WaitingToDeploy troops are hidden from combat/observation until appropriate; the owning player can see its own waiting row.

Attack reach is the attacker's raw range plus its collision radius plus the target's collision radius. Minimum range is checked separately. For ordinary non-building attackers, retaining a target may allow 25 extra world units; projectile attackers can also retain a reference within a 500-unit extension at particular noninitial attack-timer phases. Sight acquisition has its own radius and rear/side clipping. This is why a table's 5-tile range should not be used as a universal center-distance cutoff.

Selection considers visible valid candidates, distance reduced by applicable row terms, building preference where configured, and default lane/tower targeting. Lane assignment and equal-distance candidate order matter. Projectile users track already-pending lethal damage and can reject a target that is expected to die within a short (600 ms) pending window. A stored reference is not necessarily discarded simply because one query temporarily rejects it after a hit starts. No test-time search or player-controlled retarget action is supplied.

## Attack timing

Every unit uses a load/attack timer in 50 ms visits. The per-unit attack period and load fields are listed on its page. Deployment, acquiring/losing a target, starting a swing, recovering a target during windup, missing due to distance and explicit stun all enter specific reference/timer paths. Sustained DPS is therefore only a summary statistic. For ordinary melee delivery, a target beyond the extended strike reach can be missed. Direct melee queues a hit to the stored target; ranged attacks create a projectile and register pending damage. Projectiles arriving later do not retroactively change attack cadence.

## Pathing and collision

Ground movement follows the lane/terrain routing grid and routes around blocked river cells through bridge corridors. It uses integer grid search/costs, waypoint progress, collision avoidance, mass-sensitive pushing and relocation. Troops may split around obstacles and block one another. Towers are static occluders and deployment blockers. In an unobstructed moving state, the row speed is the per-50 ms displacement budget (60 means nominal 1.2 tiles/s, 52 means 1.04 tiles/s, 90 means 1.8 tiles/s). Movement budget is computed from row speed plus active modifiers; routes can be reconstructed immediately when target references change. Collision displacement is integrated in limited substeps, so replacing motion with straight-line speed×time is not equivalent.

Fireball requests pushback only for movable, living, nonhidden troops without ignore-pushback/no-pushback flags. Static towers do not move. Pushback uses a decelerating budget (25 world-unit reductions per visit), updates target coordinates and participates in collision/routing. Giant's ignorePushback flag is documented in its entity page. No player can directly issue movement commands to a deployed troop.

## Damage and hit order

World entities run holder phases in deterministic kind/ID order. For each tick the holder cleans up/adopts pending objects, snapshots the sorted live list, rebuilds spatial/terrain overlays, folds pre-hook tags, admits pending actions (phase1), runs targeting/movement/HP/buff component passes, runs listed action effect rules, admits pending actions (phase2), runs entity post-hooks, drains hits, admits pending actions (phase3), swaps grids, and performs cleanup/admission. Objects created mid-tick do not retroactively enter the original snapshot. Removal notices have their own fixed recipient lists, so children created during a notice do not receive that same notice. Hits are enqueued during attacks/projectile/area effect rules, then drained after post-hooks. The target may die before a later hit drains, and dead objects remain listed until removal cleanup. A dead object is not the same as an absent health component. Ended/held/immune/hidden/untouchable/no-damage flags can suppress a hit; guards are not encoded as a natural policy loss.

Direct attacks apply one single-target hit. Projectile impacts use the projectile's own damage and crown adjustment. Area victim selection tests target circles/footprints, visibility, side and air/ground filters, with deterministic victim order and optional shared-chain de-duplication. Arrows uses one de-duplication chain per wave, so overlapping ten arrows do not multiply one victim's wave damage by ten. Zap uses its typed filter damage and applies stun during the area effect rule before the deferred damage drain. Fireball damages first through the projectile area pipeline and requests pushback for eligible victims.

## Fixed-level arithmetic

The tables store base values and rarity-relative level fields. Card HP/damage at level 11 uses `steps=10-relativeLevel`, then `floor(base*rarityMultiplier[steps-1]/100)` for positive steps. King/tower HP/damage use their own iterative percentage modes, with integer truncation at each step. The generated values in this wiki are checked against native config.hpp; they are not rounded live-game website values.

Crown-tower projectile/direct damage uses `ceil((100+max(adjustment,-100))*damage/100)`. Fireball has −77 (23%); Arrows has −80 (20%). Crown damage is rounded per hit/wave. Zap instead has separately scaled typed damage 192/48. There are no armor, damage-type resistances, critical hits, healing, shields or random damage rolls in the reachable plain fixed8 unit rows. Arrows scatter and deck shuffle still use deterministic seeded random streams.

## Stun and state changes

ZapFreeze slows movement and attack timer advancement by 100% for 500 ms, clears/blocks combat references through the existing gate, and refreshes an existing same-row buff instead of independent stacking. Ordinary deployment countdown is not configured to be slowed by character speed. State changes call immediate combat-gate/routing effect rules. The supported normal states are Standing (0), Moving (1), Attacking (2), Deploying (4) and WaitingToDeploy (11). Dashing/jumping/etc. are unsupported in this mode, not latent extra abilities.

King activation is a separate staged action: waiting while inactive; upon own King damage or own Princess removal, queue a 3,300 ms activating action; fold inactive/activating tags in the pre-hook; retain finished actions until their holder release pass. It is not instantaneous awaken-on-hit. Both Princess towers are ready to fire from the initial normal state.
